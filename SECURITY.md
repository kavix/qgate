# Security Policy

## Supported Versions

We release patches and security fixes for the active development stream.

| Version | Supported          |
| ------- | ------------------ |
| main    | :white_check_mark: |
| < 0.1.0 | :x:                |

## Reporting a Vulnerability

The **qgate** team takes the security of cryptographic implementations and supply chain enforcement very seriously.

If you believe you have discovered a vulnerability, security flaw, or cryptographic weakness:

1. **Do not disclose it publicly.** Please do not report security vulnerabilities through public GitHub issues or discussions.
2. **Email the maintainers directly** at `kavix@yahoo.com` with:
   - A clear description of the vulnerability.
   - Steps to reproduce or a proof of concept (PoC).
   - Any potential impact on signature verification, admission bypass, or denial of service.
   - Suggested mitigations if known.

### Response Timeline

- **Initial Acknowledgment:** Within 48 hours of receipt.
- **Assessment and Confirmation:** Within 7 business days.
- **Fix and Advisory:** We will coordinate disclosure timelines with you to ensure affected users can apply updates before public announcement.
